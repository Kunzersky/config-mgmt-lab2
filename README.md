# Визуализатор зависимостей Cargo

CLI-приложение для анализа зависимостей Rust-пакетов из crates.io или
локального тестового графа. Проект выполняется по этапам практической работы
№ 2, вариант 12.

## Этапы

Этап 1: CLI принимает настройки и выводит их в формате `ключ=значение`.
Этап 2: прямые зависимости считываются из crates.io без Cargo и сторонних
библиотек.
Этап 3: зависимости обходятся BFS с рекурсией; циклы и фильтр поддержаны.
Этап 4: `--order` показывает dependency-first порядок; при цикле завершает
работу с понятной ошибкой.
Этап 5: выводит Graphviz DOT, создает SVG и по `--tree` печатает ASCII-дерево.

## Параметры

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя анализируемого пакета; обязательно. |
| `--version` | Версия crates.io; если не задана, выбирается последняя стабильная. |
| `--repository` | URL crates.io либо путь к JSON-графу. |
| `--test-mode` | Включить работу с локальным графом. |
| `--output` | Имя выходного SVG; по умолчанию `dependencies.svg`. |
| `--tree` | Включить вывод зависимостей в виде ASCII-дерева. |
| `--order` | Вывести порядок загрузки, зависимости перед родителями. |
| `--filter` | Исключить пакеты, в имени которых есть подстрока. |

## Запуск и тесты

```sh
./run.sh --package serde --repository https://crates.io
python3 -m unittest discover -s tests
```

Если `--version` не задан, выбирается последняя стабильная версия пакета.
Для указанной версии запрашиваются именно ее зависимости. Показываются
зависимости `normal` и `build`; `dev` зависимости исключены.
Registry API возвращает декларации, поэтому optional-зависимости не
разрешаются по feature-набору проекта.

Программа сообщает об ошибке при неверном имени пакета, URL, тестовом пути
или расширении выходного файла.

Тестовый граф задается JSON-объектом, где ключи и имена зависимостей состоят
из заглавных латинских букв. Пример графа находится в
`examples/repository.json`.

## Порядок загрузки и Cargo

```sh
./run.sh --package A --repository examples/repository.json \
	--test-mode --order
mkdir /tmp/cargo-compare
cd /tmp/cargo-compare
cargo init --bin --name cargo-compare
cargo add serde
cargo tree -p cargo-compare
```

Приложение строит топологический порядок по декларациям crates.io: зависимости
идут раньше родителя, общая зависимость выводится один раз. `cargo tree`
показывает уже разрешенное дерево проекта с учетом версии из lock-файла,
активной платформы и выбранных features. Поэтому расхождения ожидаемы для
optional/target-specific зависимостей и транзитивных версий; тестовый граф
показывает только явно заданные ребра.

## Примеры визуализации

Каждый запуск печатает Graphviz DOT и сохраняет SVG с выбранным именем. Три
различных корневых пакета тестового репозитория:

```sh
./run.sh --package A --repository examples/repository.json --test-mode \
	--output output/a.svg --tree
./run.sh --package B --repository examples/repository.json --test-mode \
	--output output/b.svg
./run.sh --package C --repository examples/repository.json --test-mode \
	--output output/c.svg
```

Граф для `A` включает `B`, `C`, общую зависимость `D` и ветвь `E -> F`;
для `B` строится `B -> D`; для `C` строится `C -> D` и `C -> E -> F`.
SVG-файлы являются результатом запуска и не хранятся в git.

Каждый запуск сохраняет DOT рядом с SVG с расширением `.dot`. Если установлен
Graphviz, SVG создает `dot -Tsvg`;
иначе используется встроенный SVG-рендерер. DOT-файлы и SVG не хранятся в git.

Для реального сравнения запустите приложение для `serde` с crates.io URL и
сопоставьте DOT/SVG с `cargo tree -p cargo-compare`. Cargo-вывод зависит
от `Cargo.lock`, features и target; генератор показывает API-декларации
пакета и потому может включить optional-зависимости, не активированные в
проекте. В текущей среде сравнение не запускалось: `cargo`/`dot` не установлены,
а запрос к crates.io ограничен сетью; приведенные команды предназначены для
локальной проверки.
